# 0011-Terminal split ownership

## 状态

已接受

## 背景

终端分栏最初建模为工作区级的单一状态（`WorkspaceState.terminal_split:
Option<TerminalSplitState>`），因此任意时刻全工作区只允许一个分栏。这带来三个
系统性缺陷（issue #5）：

1. 分栏创建时会按 target/project+cwd "复用"标签栏中的独立 Tab，导致同目标
   的第二个 Tab 从标签栏消失、关闭分栏时被直接销毁。
2. 任何导航（新建/切换 Tab）都会收掉分栏；分栏没有自己的属主，生命周期与
   活动视图耦合。
3. 分栏按钮的亮灭与"全局是否存在分栏"绑定，而不是与当前 Tab 绑定；
   在 Tab2 开分栏后到 Tab1 再开分栏，会顶掉 Tab2 的分栏。

这三个症状同源：分栏应该属于它开启时的那个 Tab，而不是整个工作区。

## 决策

分栏状态从工作区全局移到**属主对象**上：

- `Tab`（远程）与 `LocalSession`（本地）各自持有
  `terminal_split: Option<TerminalSplitState>`，每个属主至多一个分栏，不同
  Tab 的分栏独立共存。
- 属主是分栏创建时的活动视图（`split.left`）；只有属主正被展示时，该分栏
  参与渲染、焦点与状态栏（按钮亮灭随当前 Tab 的分栏）。
- 分栏右窗格总是新建独立会话（远程=新终端，本地=新 PTY），绝不取用标签栏
  中已有 Tab/会话。
- 生命周期边界：
  - 分栏随属主销毁；关闭右窗格只清空分栏。
  - 属主关闭时分栏激活 → 右窗格接管成为活动视图；分栏隐藏 → 右窗格退休
    （无活动销毁，有活动保留为普通标签）。
  - 分栏按钮在属主 Tab 上再点 = 关闭该分栏（确认后销毁右窗格）；在别处点
    = 为当前 Tab 新建分栏，不动其他 Tab 的分栏。
  - 批量清扫（close all / close others）清空涉及的分栏，右窗格与其他会话
    一视同仁。
- 分栏宽度仍由 AppShell 全局共享（UI 偏好，不随属主）。

## 结果/代价

标签栏行为恢复直观：每个 Tab 独立，分栏只看得到当前 Tab 的布局，切走保留、
切回还原；状态栏按钮与实际可见分栏一致。代价是 `is_split_secondary`（标签栏
跳过右窗格）与分栏查找从单一状态变为遍历各属主，会话数量级下开销可忽略；
批量清扫必须显式清理各属主的分栏，不能再依赖"唯一的 split 被拆掉"。

## 测试

registry 纯测试覆盖：属主聚焦、隐藏属主关闭/退休、独立共存、批量清扫清空、
索引重映射。渲染与按钮状态依赖 `active_split()` 契约。
