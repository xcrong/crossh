# 本地会话标签固定与重命名（重启持久化）

## 背景

用户希望给标签加「固定」和「重命名」能力，并要求两者在应用关闭再启动后保持：
固定标签在重启后自动重新打开，并继续显示用户自定义的标签名。范围限定为本地会话
（本机 shell 标签）。本地会话是 Zed PTY 进程，重启后原进程必然已结束，因此
「恢复」只意味着重开一个新 shell 到同一目录并沿用自定义名称，不恢复进程内部状态。

现状：本地会话标签的显示名来自终端标题（`tab_title`），会话生命周期完全运行时化，
重启后除最近目录列表外没有任何会话级状态可恢复；标签条也仅展示当前活动目录下的
会话，没有「固定置顶」的概念。

## 目标

1. 本地会话标签可被固定；固定后标签显示固定标识并置顶排列。
2. 固定状态与自定义名称写入持久化设置；固定标签**按项目归属**：标签条只在所属项目（活动会话的 `project_dir`）内置顶显示；**启动时不自动打开任何会话**（固定记录保留在持久化中，不立即恢复）；用户打开某项目时，该项目的固定记录随项目视图恢复——**有固定记录的项目不再额外打开普通会话**，无固定记录的新项目打开一个普通会话。固定标签显示原自定义名称。
3. 固定标签可取消固定、可重命名、可正常关闭，所有操作同步持久化。
4. 固定记录在目录失效、会话关闭等场景下自动清理，不留下失效记录，也不阻碍启动。

## 非目标

- 不固定、不恢复远程终端 / SFTP / 转发标签，也不改变 SSH 连接的恢复行为。
- 不为普通（非固定）本地会话提供重命名入口；避免产生无法持久化的临时状态。
- 不恢复终端进程内部状态（cwd 之外的原 shell 环境、运行中的命令、未保存输入）。
- 不支持拖拽排序（本次不实现）；但固定记录以稳定 `pin_id` 标识身份、以列表顺序标识位置，拖拽排序可在未来以纯位置重排方式加入而不改变持久化格式。
- 不改变标签条布局尺寸、关闭确认流程、标签滚动行为或最近目录数量上限。
- 不引入新的持久化文件；继续使用现有 `settings.toml`。

## 行为契约

1. 当用户对本地会话标签选择「固定」时，该会话应进入固定状态并分配一个持久化稳定的 `pin_id`；观察到标签置顶显示（固定标签按持久化列表顺序排在标签条最前，**仅限所属项目视图内**）并带有固定图标标识，同时设置快照中新增一条包含 `pin_id`、`project_dir`、`cwd` 的记录（`custom_name` 初始为空）。
2. 当固定会话存在自定义名称时，标签应显示自定义名称而不是终端标题；当名称为空时回退到默认标题逻辑。
3. 当用户对固定标签选择「重命名」并确认时，新名称应立即生效（标签显示更新）并持久化；取消时不应有任何变更。
4. 当重命名提交的文本为空白时，应清除自定义名称，标签回退到默认标题逻辑，持久化记录中原名称被清除。
5. 应用启动时不得自动打开任何本地会话，也不得恢复任何固定记录——无论持久化设置中是否存在固定记录或 `recent_dirs`（启动界面为无会话的空状态/侧栏列表，与无固定记录时完全一致）。固定记录在启动时保留在持久化列表中（失效目录仍按契约 6 清理），待用户打开对应项目时按契约 11 恢复。
11. 当用户打开（激活）一个项目目录时：若该项目存在固定记录，只恢复该项目尚无会话的固定记录（shell 在记录的项目目录/cwd 下启动，标签置顶、显示自定义名称），**不额外打开新的普通会话**（固定标签即代表该项目的工作会话集合）；若该项目没有固定记录，打开一个普通会话（现状）。恢复时固定身份（`pin_id`/自定义名称）必须应用到**本次恢复创建的新会话**本身，不得依赖「当前活动会话」；目录已失效（`project_dir` 或 `cwd` 不可打开）的记录应被跳过并**即时从持久化设置清理**（等价于契约 8 的关闭清理，不等待下次启动），且清理/跳过不得改写任何既有会话的身份。恢复完成后若该项目仍无任何会话（记录全部失效），应兜底打开一个普通会话，保证激活必有会话。已有会话（用户手动固定或先前已恢复）的记录不得重复打开，也不得改写其内容。
6. 当应用启动时持久化固定记录对应的目录已不存在（删除、改名、普通文件、不可访问）时，启动应成功，该记录应被跳过并从持久化设置中清理。
7. 当用户对固定标签选择「取消固定」时，会话应保持打开但回到普通标签行为（不再置顶、无固定标识），持久化记录应被移除。
8. 当固定标签被关闭（关闭按钮、关闭其他标签、会话进程退出）时，会话应被关闭且其持久化记录被移除，重启后不再恢复。
9. 当用户对同一会话重复执行「固定」时，不应分配新的 `pin_id`，持久化记录不应产生重复条目，也不应改变既有记录的顺序与内容。
10. 当设置保存失败时（固定/取消固定/重命名/清理路径），当前内存状态应保持原行为，应用不应崩溃或退出，错误应按现有设置持久化错误路径记录日志。

## 边界与错误

- 固定记录的身份键为持久化 `pin_id`（`u64`，记录内唯一）；新 `pin_id` 按现有记录 `max + 1` 推导（空列表从 1 开始），存续记录之间永不冲突；记录移除后其 id 可能被复用（当它恰为当前 max 时），因此任何依赖身份的渲染/恢复逻辑都以运行时记录的 `pin_id` 为准。`pin_id` 与列表位置解耦，排序只由列表顺序决定（为未来拖拽排序预留：重排只改位置不改身份）。
- 固定标签**按项目归属显示**：标签条只渲染「当前活动项目」（活动会话所属 `project_dir`；固定会话按其 `project_dir` 与活动项目比较）内的固定会话。切换到其他项目时，原项目的固定会话保持打开但不显示，切回后重新可见；不存在「跨目录置顶」。
- 固定标签**按项目归属恢复**：启动不自动打开任何会话；打开/激活项目时恢复该项目尚无会话的记录（契约 11），且激活有固定记录的项目**不额外打开普通会话**。同一 `project_dir` 内多条记录全部恢复，跨项目记录互不干扰；同一会话重复固定只保留其既有 `pin_id` 记录。
- 恢复路径的失效记录**即时清理**（契约 11 Rev-4）：运行中记录目录失效（删除/改名/不可访问）→ 该记录跳过恢复并即时从持久化设置清理（不等下次启动），恢复后项目无会话时兜底打开普通会话；失效记录绝不改写任何既有会话的固定身份。
- **「进入项目」与「显式打开终端」语义区分**：激活（侧栏/空状态点击）走契约 11——有固定记录的项目只恢复固定标签、不额外开普通会话；右键「打开本地终端」、标签条 `+` 按钮、分栏打开等显式动作**总是创建新普通会话**，随后幂等恢复该项目的固定记录（已全部恢复时仅补齐不重复）。
- 新固定的记录追加到持久化列表末尾（置顶区内排在最后）；删除/取消固定不影响其他记录的 `pin_id` 与顺序。
- 重命名弹窗打开期间会话被关闭：提交时若会话已不存在，静默忽略，不写持久化。
- 固定会话被「关闭其他会话」操作波及而关闭时，走契约 8 的清理路径。
- 恢复过程打开的会话仍遵守现有最近目录规则（写入最近目录并显示在侧栏 Local 分组），不影响既有恢复/排序/去重规则。
- 固定记录列表为空不是错误；空列表时启动行为与现状完全一致。
- 固定记录总数无需设上限（本地会话数量本就由用户手动管理）；如实现中发现需要上限，须在评审中说明。

## AI 评审意见

- 可测性：固定/取消固定/重命名的持久化变更、去重、失效清理、空白名称回退、启动恢复均可通过纯函数与设置快照测试观察；标签渲染行为由 GPUI 测试覆盖或人工确认。
- 错误路径：覆盖保存失败（内存状态保持）、重命名弹窗期间会话关闭、目录在启动时失效、重复固定、空白名称、被「关闭其他」波及。
- 非目标：明确排除远程标签、非固定标签重命名、进程状态恢复与布局改动，范围控制在本地会话标签生命周期。
- 平台影响：设置持久化测试为纯逻辑，跨平台一致；本地验证 macOS arm64。
- 纪律冲突：固定记录语义归 workspace feature，持久化层不承载业务规则；逻辑模块保持无 gpui 依赖。
- 待人工确认：① 固定身份为持久化稳定 `pin_id`，同一目录（甚至同一 `cwd`）下允许多个固定标签并存，各自独立记录与恢复；同一会话重复固定不新增记录。`pin_id` 与列表位置解耦，为未来拖拽排序预留；② 非固定标签不提供重命名入口；③ 任何关闭路径（含「关闭其他」）都会移除固定记录，重启后不再恢复。
- Rev-1 修订记录（2026-08-18，用户实测反馈）：原契约 1「跨目录可见」与契约 5「启动恢复全部」与目标 2「按项目归属」矛盾，实现跟了契约导致项目一的固定标签显示在项目二。本次修订回到目标 2 语义：契约 1 限定「仅属项目视图内置顶」、契约 5 限定「启动只恢复当前项目」、新增契约 11「激活项目时恢复该项目尚无会话的固定记录」。持久化格式与 `pin_id` 语义不变，仅消费侧（渲染/恢复）按项目过滤。
- Rev-3 修订记录（2026-08-18，用户实测反馈）：用户观察到进入有固定标签的项目时除恢复固定标签外还会多开一个新标签。本次修订契约 11：「有固定记录的项目激活时只恢复固定标签、不额外打开普通会话；无固定记录的新项目才打开普通会话」。实现为 `activate_local_dir` 按项目固定记录存在性跳过普通会话打开。
- Rev-4 修订记录（2026-08-18，代码评审）：审查发现恢复循环把 `pin_id` 应用到「当前活动会话」（`apply_pin_to_session` 依赖 `active_view`），当记录目录失效（创建会话失败）时会污染其他项目会话的身份，且失效记录在运行中不清理、激活后可能无任何会话。本次修订契约 11：固定身份只应用到恢复创建的新会话（`open_local_session` 返回会话 id）、失效记录跳过并即时清理、恢复后无会话兜底打开普通会话。
