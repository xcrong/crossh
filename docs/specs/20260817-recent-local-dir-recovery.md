# 失效最近本地目录恢复

## 元数据

- 创建：2026-08-17
- 相关 ADR：`docs/adr/0004-feature-owned-settings.md`、`docs/adr/0012-spec-driven-development-loop.md`
- 相关 issue / 路线图项：无
- CI 平台影响：`全部`

## 背景

Crossh 会把打开过的本地目录记录到最近目录列表，并在下次启动时恢复到主机侧栏的
Local 分组。启动恢复目前会忽略已经不存在的目录，但运行时同步可能再次把失效记录
加入目录视图；点击这类记录还可能把工作目录降级成 `/`。这让目录删除、改名和启动时
的竞态行为不一致，也可能让用户误以为打开了原项目。

## 目标

1. 失效的最近目录不会阻止 Crossh 创建主窗口或完成启动。
2. 失效目录在启动和运行时同步后都不会出现在 Local 侧栏、侧栏 Rail 或空状态页的最近目录入口中。
3. 已确认失效的最近目录从当前设置快照和持久化记录中移除，避免每次启动重复恢复。
4. 目录在用户点击前后消失时，不创建本地终端，也不把该操作改为打开 `/`。
5. 仍然存在的目录继续按现有规则恢复、排序、去重和打开。

## 非目标

- 不搜索改名后的目录，也不尝试自动推断新路径。
- 不改变远程主机、SSH 配置或远程工作目录的恢复行为。
- 不改变最近目录数量上限、目录选择器或侧栏布局。
- 不自动创建不存在的目录。

## 行为契约

1. 当设置中同时包含存在的目录和不存在的目录时，启动应该成功；观察到主窗口创建，且 Local 分组只包含存在的目录。
2. 当设置中的最近目录全部不存在时，启动应该成功；观察到应用显示无本地项目的正常空状态，而不是进程退出或窗口创建失败。
3. 当启动或运行时同步发现最近目录不存在、已改名、是普通文件或无法作为目录访问时，应该从当前最近目录状态和持久化设置中移除该记录。
4. 当目录在侧栏显示后、用户点击前消失时，点击应该保持当前工作区状态，不创建以 `/` 为工作目录的新终端。
5. 当目录在同步期间已经失效时，重复同步应该保持相同结果，不重复写入失效记录，也不重复产生副作用。
6. 当最近目录仍然存在时，恢复和打开行为应该与修复前一致。

## 边界与错误

- 清理设置失败时，当前内存状态仍必须过滤失效目录，应用不得因为保存失败而启动失败；保存错误按现有设置持久化错误路径记录日志。
- 目录检查与终端创建之间存在竞态时，失效路径不得被替换为根目录；应放弃本次打开操作。
- 路径规范化后的等价路径仍遵守现有去重和排序规则。
- 目录列表为空不是错误，应继续渲染正常的空状态和打开目录入口。

## 接口与状态变更

- 持久化字段名称和 TOML 格式不变；仅允许在读取/同步时删除已确认失效的目录值。
- 不新增公开 API、进程边界或网络协议。
- 最近目录的有效性规则仍归 `features/workspace` 所有，设置持久化层只负责快照读写。

## 平台影响

- macOS、Linux 和 Windows 的本地目录存在性、重命名和权限行为都属于本次契约。
- 本地只验证 macOS arm64；Linux 和 Windows 的路径行为由对应 GitHub Actions job 验证。

## AI 评审意见

- 可测性：启动过滤、运行时清理、点击竞态、保存失败和幂等同步均可通过纯逻辑测试或设置快照测试观察。
- 错误路径：覆盖目录删除/改名、普通文件、不可访问目录、保存失败和检查到创建之间的竞态；不把空列表当错误。
- 非目标：明确排除路径猜测、远程恢复、目录创建和 UI 改造，范围保持在 workspace 最近目录生命周期。
- 平台影响：声明 macOS 本地验证以及 Linux/Windows Actions 责任；未假设平台特定的路径分隔符。
- 纪律冲突：设置行为仍由 workspace feature 负责，持久化模块不承载目录语义；不触碰逻辑/UI 分层边界。
- 待人工确认：本规格选择自动删除已确认失效的最近目录记录，而不是保留以等待外置卷重新挂载；这是唯一需要在实现前确认的产品行为取舍。
