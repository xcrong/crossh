# v0.43.0 — 链接预览上 Windows，网页卡片能刷新，笔记搜索不漏中文

> 2026-11-10 · 基于 v0.42.0 的 6 个提交

## ✨ Highlights

### 链接预览不再只有 macOS

- Windows 上点终端链接同样弹出应用内的「临时网页」卡片，复用同一张卡片、同一套坐标与 DPI 处理（`wry` 依赖门控改为 `cfg(any(macos, windows))`，`default-features = false` 保留，不引入 `os-webview`）
- WebView2 运行时缺失时卡片建不出来，按原行为回退系统浏览器，按钮不会变成死键
- macOS 专有的 8 处 `cfg` 收敛成 `#[path]` 一处选择（`link_preview.rs` / `link_preview_unsupported.rs`），其他模块不再关心平台
- Linux 仍是占位实现、回退系统浏览器：X11 理论上能嵌，代价是 `gtk::init()` + 推进 GTK 主循环 + GTK/WebKitGTK 依赖，Wayland 无路径——属成本决策，不是能力缺失

### 网页卡片能刷新，也看得见加载状态

- 卡片 header 多一个按钮位：空闲是「刷新」，加载中换成「停止加载」，分别重载当前页 / 中断本次加载
- 加载状态只有 WebView 给的开始 / 结束二态，不做假进度转圈；macOS 加载失败时 WebKit 不回结束事件，所以停止按钮同时负责把可能卡住的「加载中」清掉，断网点一下就能恢复
- 后退 / 前进改走 WebView 原生历史（不再注入 `history.back()` 脚本），不会被页面自己的路由或 `history` 覆写拦掉

### 笔记搜索不再漏中文

- 检索改为 FTS 与正文子串结果的并集：原先「FTS 有结果就直接返回」的短路会让 `hello 天气` 这类中英混排查询漏掉中文笔记
- 相关度排序收拢到纯函数：置顶 → 命中次数 → 首次命中位置 → 更新时间 → id，两条检索路径只用都能算出的证据
- FTS 出错时降级为子串扫描并记日志；纯空白查询仍等价于列出全部

## 💅 Improvements

- 新增 `ci.yml`：Windows / Linux 的 `cargo check` 不再等到发版才暴露跨平台编译回归（此前只有 tag 触发的 `release.yml`）
- README 与 `docs/architecture.md` 同步检索语义；架构决策记录写明「分屏固定 2×2 四格，不做递归 pane tree」是刻意边界

## 🔧 Chores

- 引入 OpenSpec 规格驱动流程（`openspec/` 与六个 `openspec-*` 技能），并把「变更提案必须先评审、结论落在 change 目录的 `review.md`」写成硬门禁
- 工程笔记补记加载状态的坑：macOS 上 wry 不转发 `didFailProvisionalNavigation`，加载失败收不到 `Finished`

## 📦 升级说明

- 无需手动迁移；macOS / Windows 升级后网页卡片多一个刷新按钮
- Windows 需要 WebView2 运行时（Windows 11 自带），缺失时回退系统浏览器；Linux 行为不变
- 已知边界：加载图标只在 WebView 报告事件时翻转，页面在首字节到达前仍显示「刷新」；Windows 实机冒烟（`link-preview-multi-platform` 的 C2 条件）仍待确认
