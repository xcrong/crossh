# v0.47.2 — Git 状态跨窗口分屏一致

> 2026-11-26 · 基于 v0.47.1 的 1 个提交

## ✨ Highlights

### 底部 Git 状态跨窗口/分屏实时一致

此前同一目录在不同窗口、分屏打开时，底部 Git 分支/干净度指示器各刷各的：
有的窗口已变绿、另一个还停留在旧分支，切回来还要再闪一次。本版本改为同一目录共享同一份数据源。

- **所见即所得**：同一目录无论开几个窗口、几个分屏，底部指示器显示同一结果，不再出现“这边已切换分支、那边还是旧分支”
- **命令行操作即时跟上**：终端里 `git checkout / commit / pull` 回车后，指示器随即刷新，不用切焦、不用等下一轮定时
- **分屏多的仓库不再卡顿**：同仓多分屏只查一次 Git，后开的分屏直接复用，前台切换更顺

## 💅 Improvements

- **定时 fetch 同样按目录去重**：定轮 `fetch` 按 distinct cwd 调度，同仓多分屏只 fetch 一次，避免多项目同时 fetch 惊群（`fetch_then_refresh_git_status`）
- **定时刷新改为全量活 pane**：此前每轮只刷聚焦 pane，切回来才补刷其余 pane；现在每轮按去重后的目录刷一遍所有存活 pane，后台窗口回来时已经是对的（`src/features/workspace/shell/mod.rs`，`refresh_all_panes`）
- **跨窗口收敛可预期**：各窗口 tick 相位差仍各自调度一次，但共享缓存的在途合并保证同时只 fork 一个子进程，结果落盘即广播收敛
- **路径写法差异自动归一**：`/tmp` 与 `/private/tmp` 这类同目录不同写法视为同一数据源，避免重复查询与状态分裂（`canonical_key`，`dunce::canonicalize`）
- **非仓库结论同样共享**：探明“此目录不是 Git 仓库”后同样广播复用，不再每个分屏反复 fork 试探

## 🛠 Fixes

- **跨窗口不同步**：新增进程级 `GitStatusCache`（`src/features/workspace/git_cache.rs`），以 canonical cwd 为 key 去重与广播，各窗口 `observe_global` 各自扇出（`9988896`）
- **同窗分屏重复 fork**：同 cwd 一次 `inspect` 完成后直接扇出到本窗所有同目录 pane；已有在途请求时后来者不再 fork，只等广播（`apply_status_to_same_cwd` + `try_start / is_in_flight`）
- **命令执行后状态滞后**：`CommandFinished`（含 `git commit / push` 等）同样触发 `refresh_git_status`，与 `PromptReached` 合并去重，同时只 fork 一次（`src/features/workspace/shell/workspace_connection.rs`）
- **旧值残留**：`CwdChanged` 只清本 pane 旧值，不清空共享缓存，其余同仓 pane 不被误伤；`None`（非仓库）正确落盘广播，避免反复重试
- **竞态不丢更新**：抢占失败的 pane 撤销本次预占并等待赢家广播；完成侧先 `complete` 落盘再扇出本窗，无变化不 `notify`，避免多余重绘
