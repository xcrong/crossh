# v0.44.2 — 会话环境跟随调用方，不再继承 daemon 首启环境

> 2026-11-15 · 基于 v0.44.1 的 1 个提交

## 🛠 Fixes

- 会话环境不再冻结在 daemon 首次拉起那一刻：之前所有会话（`run --`、新终端）都继承常驻 daemon 自身的环境；macOS 上从 Finder 拉起的 daemon 只有 `PATH=/usr/bin:/bin:/usr/sbin:/sbin`，导致 `crossh run -- npm/cargo/brew…` 全挂，代理变量与 API Key 也进不来（GUI 交互 shell 靠 `.zshrc` 自救才没暴露）
- 建会话请求新增 `env` 字段携带调用方快照：CLI 在哪调起就用哪的环境（和切分前的进程内 spawn 语义一致）；daemon 侧 `env_clear` 后装基线再叠集成/标识变量，`PWD` 跟随请求目录，`SHELL` 从调用方解析（daemon 缺 `SHELL` 也不再掉到 `/bin/sh`）
- 兼容：老客户端不带 `env` 时回落 daemon 自身（0.44.x 行为）；线形只增字段，新 daemon 接老包、老 daemon 忽略新字段都能建会话

## 📦 升级说明

- 无需手动迁移；`run --` 与新开终端即时生效
- 已在运行的贫瘠 daemon 会被按需拉起的新版替换（单实例接管），或 `crossh daemon stop` 后重进
