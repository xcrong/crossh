# Git 查看器看不到新增文件内容

## 症状

Git 查看器里新出现的未跟踪文件在变更列表中可见，但右侧 diff 面板一直是空白/「无改动」；在编辑器里把内容写进该文件并保存后仍然不刷新，只有切换选中项（点别的文件再点回来）才能看到内容。已跟踪文件把一行原地改写成同样行数时也会停留在旧内容。

## 根因

周期刷新（2s）用 `FileChange` 的元数据比较来决定是否重读 diff。未跟踪文件不在 `git diff --numstat` 的输出里，`insertions/deletions` 恒为 0；等行数改写的已跟踪文件增删统计也不变。元数据相同就跳过重读，内容永远停在首次加载的那一帧（常见于「先创建空文件、再写入内容」）。

## 持久规则

变更列表的元数据（状态、暂存态、增删行数）不是文件内容的指纹，不能用来决定是否重读 diff。扫描成功后一律重读当前选中条目的 diff，由 `GitSession::apply_diff` 比较新旧 `FileDiff`：内容相同返回 false、不 `notify`，用「重读但不重绘」同时保证正确性与轮询性能。

## 验证

单元测试覆盖两条路径：同一份 `ChangeScan`（未跟踪条目元数据不变）第二次扫描仍返回 `reload_diff = true`；同一份 `FileDiff` 重复 `apply_diff` 第二次返回 false。手动验证：打开 Git 查看器 → 新建空文件 → 等它出现在列表并选中 → 写入内容保存 → 2 秒内 diff 出现内容且不闪「加载中」。
