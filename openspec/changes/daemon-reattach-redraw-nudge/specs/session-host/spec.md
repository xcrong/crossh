# Spec Delta

## MODIFIED Requirements

### Requirement: 接入时回放最近输出

新接入或重连的客户端 MUST 在随后的实时输出之前收到该会话最近的输出，使画面与终端当前状态一致。回放上限为每会话最近 512 KiB 输出；超出时按“保留最近、先丢最旧”处理，接入本身 MUST 照常完成。回放 MUST 按尺寸分段并携带每段几何，客户端按段先后重建；回放 MUST 先进入当前终端模式再画差量。回放 MUST NOT 被重复投递，也 MUST NOT 重复触发该会话已经发生过的程序状态变化与通知。

#### Scenario: 重连后画面接续

- **WHEN** 客户端断开后重新接入一个仍在运行的会话
- **THEN** 它先收到该会话最近的输出，再收到之后的实时输出
- **AND** 同一段输出不会被投递两次
- **AND** 回放不重新触发该会话已经报告过的程序状态变化或通知

#### Scenario: 回放超出上限

- **WHEN** 会话累计输出超过 512 KiB
- **THEN** 只回放最近的部分，更早的内容被丢弃
- **AND** 接入本身照常完成，不以失败或空画面收场

#### Scenario: 分段回放携带几何

- **WHEN** 会话在运行中发生过尺寸变化
- **THEN** 重连回放按尺寸分段到达，客户端按段以各自几何重放后拼接
- **AND** 分段本身不改变该会话当前尺寸

## ADDED Requirements

### Requirement: 全屏程序重连后请求重画

当会话活着、前台有程序、当前处于 `alt-screen`、且回放环已丢掉进入 `alt-screen` 的首画时，daemon MUST 发起一次条件重画请求。是否自愈取决于客户端程序是否处理尺寸变化信号；不处理的程序仍需一次按键。

#### Scenario: 首画已丢时发起请求

- **WHEN** 全屏程序的首屏已超出回放上限，客户端重新接入
- **THEN** daemon 发起一次条件重画请求
- **AND** 该请求 MUST NOT 通知客户端改布局，也 MUST NOT 改变回放环分段
- **AND** 若程序处理尺寸变化信号则显示完整屏幕，否则仍需用户按键（此为协议极限，非失败）

#### Scenario: 首画仍在时不打扰

- **WHEN** 进入 `alt-screen` 的切换仍在回放环内，客户端重新接入
- **THEN** daemon MUST NOT 发起重画请求，仅做常规分段回放
- **AND** 画面由回放直接重建完整

#### Scenario: 普通 shell 不触发重画

- **WHEN** 会话处于主屏（shell 提示符），客户端重新接入
- **THEN** daemon MUST NOT 发起重画请求
- **AND** 前端 MUST NOT 无条件抖动尺寸

#### Scenario: 短时间重复接入只请求一次

- **WHEN** 同一会话短时间内被多次重新接入
- **THEN** 只有首次接入触发重画请求，后续接入只做回放
- **AND** 中间若有真实尺寸变化，最终恢复以最新真实尺寸为准

### Requirement: 回放驱逐不对半截断

回放环丢弃旧字节时 MUST 推进到可解析边界再停，MUST NOT 以 `CSI/OSC/UTF-8` 序列中间作为回放起点。

#### Scenario: 截断对齐到序列边界

- **WHEN** 回放上限挤掉环首且切点落在转义序列或多字节字符中间
- **THEN** 驱逐继续推进到该序列结束后的下一个边界
- **AND** 客户端从边界开始解析不再出现半个序列被当成文本

### Requirement: 无客户端期间代答终端查询

会话无客户端接入期间，程序发出的 `DA / OSC 11` 等终端查询 MUST 由 daemon 按固定深色主题代答（`DA` 回 `VT102`，主题回深色），MUST NOT 悬挂等待客户端。浅色客户端的主题偏差由后续真实查询纠正。

#### Scenario: 脱离期间程序查询不 hang

- **WHEN** 会话无客户端时程序发起主题或设备属性查询
- **THEN** daemon 直接写入预设应答
- **AND** 程序继续运行不阻塞，后续接入不再补发旧查询应答

### Requirement: 引入前景判定避免误判提示符

重放是否声称“停在提示符” MUST 以内核前台进程组为准（Unix）；Windows 上无此前台信息时 MUST 按不在提示符处理、只做回放。存量提示符标志有前台命令时 MUST NOT 被采信。

#### Scenario: 全屏程序不被当成提示符

- **WHEN** shell 打印过提示符标记后把终端交给全屏程序，客户端重新接入
- **THEN** 回放 MUST NOT 报告停在提示符
- **AND** 客户端保留重建的 `alt-screen`，不将其当垃圾清掉

### Requirement: 新旧版本互操作

新 daemon MUST NOT 向无重画能力的旧客户端发送新帧；新客户端连旧 daemon 时 MUST 按旧单流解析且 MUST NOT 抖动尺寸，此时无自愈、需按键。未知帧 MUST 被跳过而非断开连接。

#### Scenario: 新 daemon 配旧 GUI

- **WHEN** 旧客户端接入已升级的 daemon
- **THEN** 连接保持，回放按旧单流可显示
- **AND** 未知帧被跳过，不导致整条接入失败

#### Scenario: 新 GUI 配旧 daemon

- **WHEN** 新客户端接入尚未升级的 daemon
- **THEN** 按旧单流解析并显示
- **AND** 不发起前端抖动，无自愈，需按键自救
