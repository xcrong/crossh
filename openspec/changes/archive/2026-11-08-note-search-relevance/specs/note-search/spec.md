# Spec Delta

## Purpose

定义笔记本地检索的行为契约：哪些笔记必须被返回、以什么顺序返回、查询出错或为空时结果如何，以及「中文不依赖专用索引」这一显式取舍的边界。它约束的是 `crossh-note` 存储层的 `search` 语义，与列表视图的展示方式无关。

## ADDED Requirements

### Requirement: 检索结果是所有匹配路径的并集

系统 SHALL 合并两条候选路径——FTS5 索引命中与正文子串命中——并按笔记 id 去重；任一条路径命中的笔记 MUST 出现在结果中，一条路径命中不得压制另一条路径的结果。两条路径都 MUST 排除已软删除（`deleted_at` 非空）的笔记，合并后不得因排序或去重把已删笔记带回列表。

查询 MUST 先按空白切分为词；每个词既参与 FTS 查询，也作为正文子串参与匹配。任一词命中（`OR` 语义）即算该笔记命中。

#### Scenario: 中英文混合查询不漏结果

- **WHEN** 库中存在内容为 `hello world` 与 `今天天气不错，适合散步` 的两条笔记
- **THEN** `search("hello 天气")` 同时返回这两条笔记

#### Scenario: 仅中文查询命中

- **WHEN** 库中存在内容为 `今天天气不错，适合散步` 的笔记
- **THEN** `search("天气")` 返回该笔记，且该笔记内容包含 `天气`

#### Scenario: 单字查询命中

- **WHEN** 库中存在内容为 `今天天气不错，适合散步` 的笔记
- **THEN** `search("气")` 返回该笔记

#### Scenario: ASCII 大小写不敏感

- **WHEN** 库中存在内容为 `hello world` 的笔记
- **THEN** `search("HELLO")` 返回该笔记

#### Scenario: 未命中返回空列表而不是错误

- **WHEN** 库中没有任何笔记内容包含查询词
- **THEN** `search("不存在的内容")` 返回 `Ok` 且结果为空

#### Scenario: 已删除笔记不出现在结果中

- **WHEN** 一条笔记命中查询但已被软删除，另一条未删除笔记同样命中
- **THEN** `search` 只返回未删除的那条，且结果中没有已删除笔记的 id

### Requirement: 结果排序稳定且可解释

系统 SHALL 按下列优先级对结果排序，且每条排序键都必须能从笔记本身推导出来：

1. 置顶（`pinned`）在前；
2. 命中次数多者在前；
3. 首次命中位置更靠前者在前；
4. `updated_at` 降序；
5. `id` 降序。

相关度 MUST NOT 依赖只有单条路径才有的量（例如 FTS 的 `bm25` 分值），否则两条路径的命中无法同尺度比较。相同输入重复查询 MUST 返回相同顺序。

#### Scenario: 置顶笔记始终在前

- **WHEN** 一条普通笔记与一条已置顶笔记都命中同一查询，且普通笔记的命中次数更多、更新时间更新
- **THEN** 置顶笔记排在前面

#### Scenario: 命中次数多者优先

- **WHEN** 两条未置顶笔记都命中查询 `work`，其中一条正文出现 `work` 三次、另一条一次，且两条 `updated_at` 相同
- **THEN** 命中三次的笔记排在前面

#### Scenario: 同分时按更新时间与 id 排定

- **WHEN** 两条未置顶笔记的命中次数与首次命中位置都相同、`updated_at` 也相同
- **THEN** 按 `id` 降序排列，顺序确定且可重复

### Requirement: 查询容错与空查询语义

系统 SHALL 在查询只含空白字符时返回与 `list()` 相同的完整列表（仅过滤已删除笔记）。查询中的 `%` 与 `_` MUST 按字面匹配而不是通配符。查询包含 FTS 语法字符（引号、`*`、`NEAR(` 等）时 MUST NOT 让 `search` 返回错误。FTS 路径失败时系统 SHALL 降级为纯子串检索并记录一条 `warn` 日志，而不是把错误交给调用方。

#### Scenario: 只含空白等价于 list

- **WHEN** 库中有三条未删除笔记
- **THEN** `search("   ")` 返回的顺序与条数与 `list()` 完全一致

#### Scenario: 通配符按字面匹配

- **WHEN** 库中存在内容为 `a%b` 的笔记与内容为 `axb` 的笔记
- **THEN** `search("a%b")` 只返回 `a%b` 那条

#### Scenario: FTS 语法字符不产生错误

- **WHEN** 查询包含未配对的引号与 `NEAR(` 片段
- **THEN** `search` 返回 `Ok`（结果可以为空），且视图层不会显示「查询失败」

#### Scenario: FTS 索引不可用时降级

- **WHEN** FTS 索引表缺失（或 FTS 查询返回错误），而正文子串路径可用
- **THEN** 结果仍来自正文子串路径且 `search` 返回 `Ok`，日志中留有 `warn` 记录

### Requirement: 中文检索不依赖专用索引，成本上限必须显式记录

系统 SHALL 让中文查询通过正文子串匹配得到结果，MAY 为此扫描正文而不使用索引。实现处 MUST 用 `ponytail:` 注释记录该路径的成本上限（随笔记数与正文大小线性增长）以及升级路径（影子 bigram 索引），使后来者知道何时该换实现。

#### Scenario: 无需额外索引即可检索中文

- **WHEN** 一个使用默认 schema 的笔记库中存在中文内容
- **THEN** 中文查询可直接命中，无需重建索引或改动 schema 版本

#### Scenario: 成本上限在代码中可查

- **WHEN** 阅读 `crates/crossh-note/src/lib.rs` 中的检索实现
- **THEN** 能找到说明线性扫描成本与升级路径的 `ponytail:` 注释
