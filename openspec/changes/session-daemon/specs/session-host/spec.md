# session-host Delta

## Purpose

定义"会话归属与接入"的行为契约：终端会话由常驻进程持有而不是由窗口持有，生命周期与任何一次前端运行无关；任意前端在完成认证与版本协商后都能发现、驱动、读取同一批会话，与它是不是 GUI 无关。

## ADDED Requirements

### Requirement: 会话的生命周期不依附于任何窗口

会话 MUST 由常驻进程持有，其存在与否只取决于会话自身的结束条件（进程退出、会话被显式关闭）或常驻进程本身终止，而不取决于任何前端窗口是否打开。前端退出、崩溃或被替换 MUST NOT 结束它未显式关闭的会话。

#### Scenario: 关闭窗口后命令继续运行

- **WHEN** 某个会话里有一个长命令正在运行，用户关闭 GUI 窗口
- **THEN** 该会话与命令继续运行
- **AND** 有命令在跑不再构成关闭窗口的破坏性后果，因此不再出现关闭确认提示

#### Scenario: 重新打开后回到原会话

- **WHEN** 用户在某个会话里启动了一条长命令，关闭 GUI 后重新启动 crossh
- **THEN** 原有的固定标签重新接入各自的同一个会话，而不是新建 shell
- **AND** 那条长命令仍在同一个会话里运行并继续产生输出，可据此区分「同一个会话」与「新建 shell」

#### Scenario: 常驻进程终止会话随之消失

- **WHEN** 常驻进程被强制结束
- **THEN** 它持有的会话一并消失
- **AND** 重新启动后得到的是新会话，系统不会声称恢复了一个仍然存在的进程

### Requirement: 一个会话可被多个前端接入，输入所有权唯一

同一会话 MUST 允许一个以上客户端同时接入并各自收到输出。任一时刻 MUST 至多有一个客户端持有输入权；不持有输入权的客户端发送的按键 MUST NOT 进入会话。任一在接客户端发送一次输入即 MUST 取得输入权，无需额外命令。输入权归属 MUST 可观察：会话列表显示每个会话当前由哪个客户端持有输入权，GUI 在失去输入权时显示只读状态；易手后这两处随之变化。

#### Scenario: 第二个客户端只观察

- **WHEN** 一个客户端已接入某会话后，第二个客户端接入同一会话
- **THEN** 第二个客户端收到输出，它的按键不进入会话
- **AND** 该会话的终端尺寸不因第二个客户端而改变
- **AND** 会话列表显示第一个客户端持有输入权

#### Scenario: 输入权持有者断开后可被接管

- **WHEN** 持有输入权的客户端断开，另一个客户端仍接在同一会话上
- **THEN** 该会话暂无输入权持有者，会话列表相应显示
- **AND** 仍在接入的那个客户端发送一次输入即取得输入权，列表与 GUI 的只读状态随之改变
- **AND** 它从此的按键进入该会话

### Requirement: 接入时回放最近输出

新接入或重连的客户端 MUST 在随后的实时输出之前收到该会话最近的输出，使画面与终端当前状态一致。回放上限为每会话最近 512 KiB 输出；超出时按"保留最近、先丢最旧"处理，接入本身 MUST 照常完成。回放 MUST NOT 被重复投递，也 MUST NOT 重复触发该会话已经发生过的程序状态变化与通知。

#### Scenario: 重连后画面接续

- **WHEN** 客户端断开后重新接入一个仍在运行的会话
- **THEN** 它先收到该会话最近的输出，再收到之后的实时输出
- **AND** 同一段输出不会被投递两次
- **AND** 回放不重新触发该会话已经报告过的程序状态变化或通知

#### Scenario: 回放超出上限

- **WHEN** 会话累计输出超过 512 KiB
- **THEN** 只回放最近的部分，更早的内容被丢弃
- **AND** 接入本身照常完成，不以失败或空画面收场

### Requirement: 接入必须完成认证

常驻进程 MUST 只接受持有当前用户令牌的客户端接入。缺失或错误令牌的接入 MUST 被拒绝，且拒绝应答 MUST NOT 泄露会话数量、标题、内容或工作目录。令牌载体 MUST 仅当前用户可读：Unix 上由文件权限保证，Windows 上依赖每用户目录的默认访问控制。

#### Scenario: 无令牌的接入被拒绝

- **WHEN** 一个不持有令牌的本机进程尝试接入
- **THEN** 握手被拒绝
- **AND** 应答中不包含任何会话信息
- **AND** 同一进程在 Unix 上以其他用户身份运行时无法读取令牌载体

#### Scenario: 令牌正确的接入

- **WHEN** 客户端出示与常驻进程发布的令牌一致的令牌
- **THEN** 握手成功，客户端可以请求会话列表

### Requirement: 版本与能力不匹配时明确拒绝

协议版本不一致 MUST 在握手阶段被拒绝，并给出可理解的失败原因；系统 MUST NOT 进入"接上了但部分不可用"的状态。拒绝时必须同时给出可执行的恢复步骤——停止旧实例的命令——否则升级后用户面对的是一次没有出路的失败。客户端不认识的能力标志 MUST 被忽略而不是导致断开，以便旧客户端连上新常驻进程时仍能使用共同子集。

#### Scenario: 版本不一致

- **WHEN** 客户端与常驻进程的协议版本不同
- **THEN** 握手在交换会话数据之前失败
- **AND** 失败原因说明是版本问题，而不是超时或连接错误，并给出停止旧实例的具体命令

#### Scenario: 未知能力标志

- **WHEN** 客户端不认识常驻进程声明的某个能力标志
- **THEN** 连接保持，双方共同支持的功能照常工作

### Requirement: 单实例与按需启动

同一用户的同一构建配置下 MUST 至多存在一个会话属主。并发启动多个前端时，后到者 MUST 接入既有实例而不是成为第二个属主。常驻进程 MUST 能在首次被任何前端请求时自动启动，也 MUST 能被显式停止。

#### Scenario: 并发启动不产生两个属主

- **WHEN** 两个客户端在常驻进程尚未运行时几乎同时发起请求
- **THEN** 最终只有一个会话属主
- **AND** 两个客户端都接入它，不出现"其中一个看不到另一个的会话"

#### Scenario: 显式停止

- **WHEN** 用户显式请求停止
- **THEN** 常驻进程结束，其会话结束
- **AND** 之后任一前端再次请求时按需重新启动

### Requirement: 任何前端都能在不依赖 GUI 的前提下完成闭环

系统 MUST 提供一条不经过 GUI 的完整路径：发现会话、创建会话、向会话写入输入、读取会话输出与命令退出码、结束会话。这条路径 MUST 在 GUI 从未运行过的机器上可用，且其结果 MUST 与在 GUI 中操作同一会话一致。

#### Scenario: GUI 从未运行

- **WHEN** 用户在没有任何 GUI 进程运行的情况下使用命令行前端
- **THEN** 能按需启动常驻进程、列出（可能为空的）会话、新建会话、在其中运行命令并取得输出与退出码

#### Scenario: 两个前端的观察一致

- **WHEN** 一条命令经由命令行前端在某个会话中执行完毕
- **THEN** GUI 之后接入该会话时，在会话的回放上限之内看到同一段输出与同一个退出状态
