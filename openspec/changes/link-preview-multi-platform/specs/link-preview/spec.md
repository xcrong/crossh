# link-preview Delta

## ADDED Requirements

### Requirement: 预览可用性按平台声明

终端链接必须先尝试在应用内预览；只有当前平台没有原生 webview 宿主时才回退系统浏览器。平台差异 MUST 是规格声明的、可观察的差异，而不是实现细节的副产品：

- macOS 与 Windows：提供应用内预览。
- Linux（含 Wayland）：MUST 回退系统浏览器，且不引入 GTK / WebKitGTK 依赖。

同一平台内不存在「有时卡片、有时浏览器」的分叉：链接进入预览还是浏览器，只取决于平台与原生视图创建是否成功。

#### Scenario: macOS 或 Windows 点击终端链接

- **WHEN** 用户在终端里点击一个 http(s) 链接
- **THEN** 链接在应用内悬浮卡片中打开，不启动系统浏览器

#### Scenario: Linux 点击终端链接

- **WHEN** 用户在 Linux（X11 或 Wayland）上点击终端链接
- **THEN** 链接交系统默认浏览器打开，应用内不出现卡片，状态栏也不出现链接预览入口

#### Scenario: 平台入口不出现死键

- **WHEN** 当前平台没有原生 webview 宿主
- **THEN** 状态栏不渲染链接预览按钮，用户无法点到一个永远打不开的入口

### Requirement: 原生网页只占卡片内容区

卡片外框、标题栏、遮罩由 GPUI 绘制，原生 webview 只允许占据内容区矩形。与网页矩形重叠的 GPUI 浮层（命令面板、右键菜单、重命名框、默认命令编辑框）打开时 MUST 隐藏原生视图；浮层关闭后 MUST 重新显示并保留页面状态（地址、滚动位置、历史）。

#### Scenario: 浮层打开时不被网页遮挡

- **WHEN** 预览卡片已显示，用户按下命令面板或右键打开菜单
- **THEN** 原生网页区域隐藏，浮层完整可见
- **AND** 浮层关闭后网页重新显示，页面仍停在原地址

#### Scenario: 卡片与网页矩形不重叠绘制

- **WHEN** 预览卡片渲染
- **THEN** 卡片边框与标题栏落在原生视图矩形之外，不会被原生视图覆盖

### Requirement: Esc 关闭预览

无论键盘焦点在 GPUI 还是已被网页接管，`Esc` MUST 关闭预览卡片。网页内按下 `Esc` 时不得残留在页面内或被浏览器默认行为吞掉。

#### Scenario: 焦点在 GPUI 时关闭

- **WHEN** 预览显示且 GPUI 持有键盘焦点，用户按 `Esc`
- **THEN** 卡片关闭，焦点回到之前的终端视图

#### Scenario: 焦点在网页内时关闭

- **WHEN** 用户已点进网页内容，随后按 `Esc`
- **THEN** 页面把该按键转回应用并关闭卡片，页面自身不响应 `Esc`

### Requirement: 预览内的导航受协议白名单约束

预览内只允许 `http` / `https` 导航。页面试图跳转到其他 scheme（`file:`、自定义 scheme、`javascript:`）时 MUST 被阻止，并交由系统处理策略；地址栏与「在浏览器打开」始终指向当前页的真实地址。

#### Scenario: 页内跳转到非 web scheme

- **WHEN** 页面内触发一个非 http(s) 的导航
- **THEN** 原生视图不导航到该地址

#### Scenario: 页面重定向后地址同步

- **WHEN** 页面发生重定向或用户点击页内链接
- **THEN** 地址栏与状态栏显示当前页真实地址

### Requirement: 原生视图不可用时回退而不是留白

原生 webview 创建失败（例如 Windows 缺少 WebView2 运行时、macOS 无可用 WebKit）或运行期销毁时，MUST 回退到系统浏览器打开同一个链接，且不留下空白卡片、不出现无效状态栏入口。

#### Scenario: Windows 缺少 WebView2 运行时

- **WHEN** 原生视图创建失败
- **THEN** 同一链接交系统浏览器打开
- **AND** 卡片不显示，状态栏入口回到「无预览」状态

#### Scenario: 预览已存在时切换到另一个链接

- **WHEN** 预览卡片已打开，用户再点另一个 http(s) 链接
- **THEN** 复用同一个原生视图加载新地址，不叠加第二个卡片
- **AND** 地址栏与状态栏同步到新地址
