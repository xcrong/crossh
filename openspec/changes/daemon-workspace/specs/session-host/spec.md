# session-host Delta

## Purpose

本 delta 由 `daemon-workspace` 提出，修订 `session-daemon` 引入的会话归属契约中两处会被工作区所有权推翻的表述：会话重连不再以“固定标签按 id 回到同一个会话”为判据，改为“布局恢复、仍在运行的会话被重新接入、已结束的会话在 pane 上重建”。

**合入前提**：`openspec/changes/session-daemon/` MUST 先 apply；代码实施可在其归档前开始，但本 delta 只在该变更归档、`session-host` 主规格存在之后才能合入，且本变更归档前 MUST 完成这次合入。若在此之前合入，主规格会保留已被推翻的固定标签场景。

## MODIFIED Requirements

### Requirement: 会话的生命周期不依附于任何窗口

会话 MUST 由常驻进程持有，其存在与否只取决于会话自身的结束条件（进程退出、会话被显式关闭）或常驻进程本身终止，而不取决于任何前端窗口是否打开。前端退出、崩溃或被替换 MUST NOT 结束它未显式关闭的会话。

#### Scenario: 关闭窗口后命令继续运行

- **WHEN** 某个会话里有一个长命令正在运行，用户关闭 GUI 窗口
- **THEN** 该会话与命令继续运行
- **AND** 有命令在跑不再构成关闭窗口的破坏性后果，因此不再出现关闭确认提示

#### Scenario: 重新打开后回到原布局

- **WHEN** 用户在某个会话里启动了一条长命令，关闭 GUI 后重新启动 crossh
- **THEN** 工作区恢复原来的项目、tab 与分屏布局
- **AND** 仍在运行的会话被重新接入，而不是新建 shell 取代它
- **AND** 已结束的会话在其原来的 pane 上按该 pane 的最后 cwd 重建
- **AND** 判定“同一个会话”的依据是该 pane 当前绑定的会话标识，而不是任何被持久化的历史会话标识

#### Scenario: 常驻进程终止会话随之消失

- **WHEN** 常驻进程被强制结束
- **THEN** 它持有的会话一并消失
- **AND** 重新启动后得到的是新会话，系统不会声称恢复了一个仍然存在的进程
